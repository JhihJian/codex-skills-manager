# 技能问题发现工作台

## 目标

让非技术使用者从一次技能使用中发现并提交问题，不要求理解技能 SHA、合同、Case、归因关系或内部状态码。工作台的职责是形成可审计的问题线索，不发布技能质量结论。

## 使用流程

1. 打开 `reviews.html`，默认进入“发现问题”。
2. 从最近使用记录选择本次任务，或选择“没有看到这次使用记录”。
3. 选择日常问题类别，填写发生了什么。
4. 可选地声明“与这项技能直接有关”，并写明原因。
5. 确认脱敏摘要和保存范围后提交，在“我提交的问题”查看可读状态。

页面状态固定映射为“已收到、待关联、已确认、正在处理、等待你确认、已解决、未采纳”。内部 `queued`、`triaged`、`shared`、Case ID 与 reason code 不作为发现流程的操作语言。

## 数据边界

提交使用 `skill-problem-discovery` 通道。服务端为其创建独立的 canonical event、Feedback Signal、Revision、可选 Target 和追加式 Action，沿用既有脱敏、目标验证、并发和处置审计机制。

- 选择使用记录但未声明直接关联时，只建立任务结果上下文。
- 只有用户明确声明直接关联且填写原因时，才建立 `skill-invocation` 目标候选。
- 没有使用记录时仍可提交，状态为待关联。
- 主动发现不计入 `user-feedback`、`process-anomaly`、正式合同失败率、质量快照或技能失败结论。

## 门禁

交付前由独立 subagent 用真实浏览器确认：默认入口清晰、可从记录或无记录路径提交、提交前有脱敏和非自动归责说明、提交后可读状态可追踪、内部代码不出现在普通流程、桌面和移动端无重叠或横向溢出。
